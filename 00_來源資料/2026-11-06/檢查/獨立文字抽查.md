# 訪談文字下載品質獨立抽查

範圍：檢查已下載訪談 HTML/Markdown 的 `<details>` 收合區塊與指定樣本。這是下載品質抽查，不查核政策事實，也未逐句對照影音。

## 結果

- 最終數量以 [驗證報告.json](驗證報告.json) 為準：整體狀態 `passed`，訪談逐字稿來源記錄 179 筆；其中 interview_article 74、transcript_page 33、article_attachment 32、transcript_attachment 38、hub_index 1、source_notes_attachment 1。本報告早先記載的 181 筆是下載中途狀態，已更新。
- 沈春華原始 DOCX 可正常作為 ZIP 開啟並通過 CRC 檢查（14 個成員）；對應的 Markdown 可嚴格以 UTF-8 解碼，含 213 個非空段落及實際訪談正文。路徑見 JSON。
- 先前抽查的 38 個長 `<details>` 區塊中，商周與 TODAY 兩份逐字內容的最後正文存在於各自獨立 transcript Markdown：商周末段「整個機制要怎麼建立起來…成功的經驗」可見；TODAY 的 00:41:06 主持人收尾及 00:41:16「謝謝！」可見。HTML 尾端可能另有 AI 校訂與權利聲明；格式與空白差異使同名文章的精確尾字串不能單獨作為完整性判準。
- 指定來源樣本（HTML body 字數 / 長 `<details>` 字數 / 對應文章 Markdown 字數）：商周 2026-11-02：18,557 / 16,636 / 19,108；范琪斐 TODAY 2026-11-04：13,724 / 12,678 / 14,687；外部舊訪談 2023-09-08：6,100 / 361 / 5,196。標題皆保留；商周/TODAY 有「尚未逐句對照影音」類提示，外部舊訪談有「依據逐字稿整理改寫」編按。
- 掃描文字檔未發現 `�` 或 `ï¿½` 編碼替代標記。未發現摘要頁被當成逐字稿的明確證據；本次抽查未列出可由下載產物直接證實的遺漏修項。

## 限制

此檢查不代表所有收合區塊都逐字完整，或任何文字與影音一致。逐字稿來源可能本身有辨識錯字、缺句；本抽查不評估內容正確性。
